# nps_wsva_app

**NPS Water Supply Vulnerability Assessment (WSVA) App**

Shiny app for exploring vulnerability scores and rankings for National Park 
Service water supplies under changing weather and hydrologic conditions.

Part of [Water Vulnerability Analytics (WaVA)](https://github.com/Water-Vulnerability-Analytics). The indicators and input data are produced by [`nps_water_vulnerability`](https://github.com/Water-Vulnerability-Analytics/nps_water_vulnerability). 
This app was split out of that repo's `rapid_app/` folder with its full commit 
history.

## Contents

- `app.R`: the Shiny app
- `calc_vulnerability_index.R`: combines indicators into the vulnerability index 
(sourced by `app.R`)
- `app_data/`: the data the app reads (indicators, index, water supplies, park
boundaries)
- `www/`: static assets, including the methods report
- `tests/`: testthat unit tests and shinytest2 browser smoke tests
- `deploy.R`: the list of files that make up the deployed app; regenerates 
`manifest.json` and publishes
- `manifest.json`: deployment manifest (files + package versions), generated by
`deploy.R`
- `data/` (gitignored symlink, not deployed): the shared raw-data folder the app
data is built from

## Running the app

From the repo root in R:

```r
shiny::runApp()
```

## Running the tests

From the repo root:

```bash
Rscript -e 'testthat::test_dir("tests/testthat")'   # unit + smoke tests
Rscript -e 'shinytest2::test_app(".")'              # whole suite via shinytest2
```

Browser smoke tests need Chrome and are skipped when it isn't available.

## Deploying

The app is hosted on shinyapps.io (`geocentroid` account, app `rapid_app`) and 
served publicly through CSU at <https://apps.gis.colostate.edu/WSVA_tool/>.

```bash
Rscript deploy.R manifest   # after changing APP_FILES or package versions
Rscript deploy.R deploy     # publish to shinyapps.io
```

`deploy.R` publishes only the files in `APP_FILES`, so `data/`, `tests/` and the 
unused files in `app_data/` never reach the server. Use it instead of the RStudio
Publish button. Deploying needs the `geocentroid` shinyapps.io token on your 
machine (`rsconnect::setAccountInfo()`); because the account and app name are 
fixed in `deploy.R`, it always updates the live app rather than creating a new
one. `tests/testthat/test-deploy-manifest.R` fails if `app.R` reads a file that 
isn't deployed or if `manifest.json` has fallen out of step.

## Updating app data

The files in `app_data/` are generated by `app_data_prep.Rmd` in 
[`nps_water_vulnerability`](https://github.com/Water-Vulnerability-Analytics/nps_water_vulnerability).
